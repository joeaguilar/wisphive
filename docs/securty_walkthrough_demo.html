Stakeholder walkthrough

Security turns Wisphive from localhost-only into a real operator surface.

The delayed work is not polish. It is the path from "use the TUI on the machine" to "approve agent work from a phone on the local network without exposing the daemon."

The current local UI is useful, but brittle for the user who leaves the laptop, works from another room, or wants phone approvals during a long agent run.

Today: secure foundations, limited reach

    Impact

      The product is technically safer than a naked LAN server, but still not where the stakeholder wants it: phone approval is not a reliable production workflow yet.

      The security gates are the product.

      These gates turn local-network exposure from "hope nobody can reach it" into a controlled device lifecycle with explicit reauthentication for dangerous approvals.

      Implemented Host and Origin allowlists

      Reject DNS rebinding and malicious-page cross-origin attempts before token validation.

      Implemented Per-device bearer tokens

      Each browser gets a distinct token stored as a SHA-256 hash, so a lost device can be revoked.

      Planned Passkey-backed pairing

      Phone enrollment becomes a device-bound credential flow, not a copied secret.

      Planned Ephemeral LAN listener

      QR pairing opens one temporary LAN surface, with a different router and one active token.

      Implemented TLS and fingerprinting

      Self-signed ECDSA certs rotate safely and expose a fingerprint for operator verification.

      Planned LAN SAN filtering

      Only useful local addresses should be advertised and trusted, avoiding Docker, VPN, and unstable interfaces.

      Implemented Sudo reauth

      Web-origin approvals for Bash, Write, Edit, MultiEdit, NotebookEdit, and ConfigChange require fresh password proof.

      Ship blocker Fail-open and CORS hardening

      LAN pairing should not ship as default until the known blocker set is closed.

      Toggle the blockers.

      The meeting story is simple: every enabled gate increases usability without changing the trust model. Every missing blocker keeps LAN support experimental.

      Where the real value is.

      Security work is the unlock for the product demo, the daily workflow, and open-source credibility.

      Mobility

      Operators can leave the laptop.

      Long agent runs become manageable from a phone. Approve, deny, and monitor the same queue without being tied to the TUI.

      Trust

      LAN access becomes intentional.

      HTTPS, allowlists, passkeys, short-lived pairing tokens, audit rows, and revocation make local-network use defensible.

      Demo

      The story becomes visible.

      A stakeholder can scan a QR code, enroll a phone, see the desktop confirm pairing, then approve a real agent action.

      Delivery path

      Sequencing is constrained because the pairing UX depends on network identity, TLS, passkeys, and a separate LAN listener.
